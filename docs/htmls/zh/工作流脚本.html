工作流脚本只准备目录、输入文件和链接，不替用户提交计算。

脚本位置： Scripts/workflow/

交互入口

运行 gpumdkit.sh 并选择 3) Workflow，各入口说明见下表。

显示完整菜单
text
+---------------------------------------------------------+
|                      WORKFLOW TOOLS                     |
+---------------------------------------------------------+
| 301) SCF batch pretreatment                             |
| 302) MD sample batch pretreatment (gpumd)               |
| 303) MD sample batch pretreatment (lmp)                 |
+---------------------------------------------------------+
| 000) Return to the main menu                            |
+---------------------------------------------------------+
Input the function number:
菜单 工作流 适用场景
301 SCF 批处理预处理（SCF batch pretreatment） 为多个结构准备 DFT 单点目录
302 GPUMD MD 采样批处理预处理 为 GPUMD 采样准备多个目录
303 LAMMPS MD 采样批处理预处理 为 LAMMPS 采样准备多个目录

1. 准备 DFT 单点计算

请在专用工作目录中操作，并把原始结构另行保存。功能 301 会在当前目录创建 struct_fp/、fp/、各计算目录和 presub.sh。

VASP 单点预处理（301 -> 1）

输入可以是多个 .vasp 文件，或一个 extxyz 文件：

text
current directory/
├── POSCAR_1.vasp
├── POSCAR_2.vasp
└── POSCAR_3.vasp

也可以是：

text
current directory/
└── sampled.xyz

脚本按以下顺序选择输入：

  1. 有一个或多个 .vasp 时优先处理 .vasp；
  2. .vasp 和 .xyz 同时存在时给出提示，只处理 .vasp；
  3. 没有 .vasp 且只有一个 .xyz 时，将该 extxyz 转成 POSCAR；
  4. 没有 .vasp 且有多个 .xyz 时，让用户选择文件。

运行菜单：

bash
gpumdkit.sh
# 选择 3 -> 301 -> VASP

所有结构只有一种元素集合时，输出保持原来的平铺结构：

text
current directory/
├── struct_fp/
│   ├── POSCAR_1.vasp
│   └── ...
├── fp/
├── <prefix>_1/
├── <prefix>_2/
└── presub.sh

对于 extxyz 输入，POSCAR 的元素顺序沿用整个轨迹中元素首次出现的顺序。 如果所有结构的元素集合相同，就沿用原来的平铺目录， 并共用 fp/POTCAR。元素集合相同但原子比例不同的结构仍属于同一组。如果 存在多个元素集合，POSCAR 会按元素顺序放入 struct_fp/<元素顺序>/，各计算 目录链接到对应的 fp/POTCAR_<元素顺序>：

text
struct_fp/
├── Al_O/POSCAR_1.vasp
└── Al_O_Te_Bi/POSCAR_2.vasp
fp/
├── INCAR
├── POTCAR_Al_O
└── POTCAR_Al_O_Te_Bi
<prefix>_1/POTCAR -> ../fp/POTCAR_Al_O
<prefix>_1/KPOINTS -> ../fp/KPOINTS
<prefix>_2/POTCAR -> ../fp/POTCAR_Al_O_Te_Bi
<prefix>_2/KPOINTS -> ../fp/KPOINTS

请根据程序列出的名称把各组 POTCAR 放入 fp/，并确保 POTCAR 中元素的顺序 与 POSCAR 头部一致。所有组共用 fp/INCAR，每个计算目录都会链接到 ../fp/KPOINTS。显式指定 k 点时，请在 fp/ 中提供该文件。如果目标文件 不存在，链接会悬空，VASP 会按 KPOINTS 文件缺失处理并使用 KSPACING。 输入的 prefix 会成为计算目录前缀，之后用 out2xyz 提取结果时，目录名会 写入 extxyz 的 config_type。

CP2K 单点预处理（301 -> 2）

先准备 extxyz 文件和模板。模板必须从 pos.xyz 读取坐标，参考模板为 Scripts/workflow/cp2k_template.inp。通过菜单运行：

bash
gpumdkit.sh
# 选择 3 -> 301 -> CP2K

交互输入为：

text
<extxyz_file> <template.inp> <prefix_name>

例如：

text
dump.xyz template.inp H2O

脚本为每个结构创建 <prefix>_<index>/，并写入 input.inp 和 pos.xyz。

从源码安装时，也可以在数据目录中直接调用脚本：

bash
python "${GPUMDkit_path}/Scripts/workflow/scf_batch_pretreatment_cp2k.py" train.xyz template.inp calc

2. 准备 MD 采样目录

GPUMD（302）

把 .vasp 文件或一个 extxyz 文件放在专用工作目录中。输入选择规则与 VASP 预处理相同：.vasp 优先；没有 .vasp 且有多个 .xyz 时会让用户选择。

bash
gpumdkit.sh
# 选择 3 -> 302

典型输入：

text
current directory/
├── POSCAR_1.vasp
└── POSCAR_2.vasp

或：

text
current directory/
└── dump.xyz

运行后通常得到：

text
current directory/
├── struct_md/
│   ├── model_1.xyz
│   └── ...
├── md/
├── sample_1/
├── sample_2/
└── presub.sh

准备结束后，把 nep.txt 和每个样本对应的 run_*.in 放入 md/。各样本目录 会链接到它们：sample_1/run.in 指向 md/run_1.in，sample_2/run.in 指向 md/run_2.in，依此类推。

LAMMPS（303）

把 .vasp 文件或一个 extxyz 文件放在专用工作目录中；两种格式同时存在时 优先处理 .vasp。

bash
gpumdkit.sh
# 选择 3 -> 303

运行后会在 struct_md/ 中创建 LAMMPS data 文件，并创建样本目录、md/ 和 presub.sh：

text
current directory/
├── struct_md/
│   ├── lammps_1.data
│   └── ...
├── md/
├── sample_1/
├── sample_2/
└── presub.sh

准备结束后，把 lmprun.in 和 nep.txt 放入 md/，各样本目录会链接到它们。

3. 运行前检查

提交前请检查：

  • 结构数量、原子和元素顺序、晶胞，以及生成的目录数量；
  • fp/ 中的 INCAR、POTCAR、KPOINTS，或 md/ 中的 nep.txt、run_*.in、lmprun.in；
  • 每个目录中的链接和文件名；
  • presub.sh 中的可执行文件、资源和调度设置（它只是一个模板）。

工作流脚本与集群、模板和软件版本有关，正式批量处理前先用少量结构试运行。计算结束后，先找出失败或不完整的样本，再继续下一步。

4. 转换计算结果

DFT 计算结束后，用以下命令转换：gpumdkit.sh -out2xyz <dir>（VASP，输出 NEPdataset/train.xyz）、-out2xyz_bec <dir>（VASP，含 Born 有效电荷），或 -cp2k2xyz（CP2K，在结果根目录运行，输出 cp2k_exyz.xyz）。详见格式转换；这些步骤如何组成完整的 NEP 数据迭代，见主动学习工作流。

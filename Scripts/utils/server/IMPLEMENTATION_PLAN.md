## 2. 设计主张：一个目录，一张内容画布

用户首先关心当前目录有什么、结果是什么。页面应回答这两个问题，而不是要求用户先选择功能模块。

### 2.1 唯一主结构

```text
┌──────────────────────────────────────────────────────────────┐
│ GPUMDkit   项目 / 当前目录                刷新   更多          │
├───────────────┬──────────────────────────────────────────────┤
│ 搜索          │ 当前目录名                    简短状态         │
│ 文件与子目录  │                                              │
│               │ [有有效 loss 才出现：紧凑曲线 + 简洁摘要]       │
│               │                                              │
│               │ [有图片就直接出现：图片预览]                    │
│               │                                              │
│               │ [有可用分析才出现：低干扰操作行]                │
└───────────────┴──────────────────────────────────────────────┘
```

这只是结构示意，不要求画出所有外框。实际页面只保留必要分隔，不把每个区域包成独立卡片。

- 左边是文件导航，右边是一张当前目录内容画布。
- 无顶层 Overview / Data / Figures / Loss 分页；无模块图标轨道。
- 面包屑是目录位置的唯一常驻来源，避免顶部、侧栏、底栏同时重复完整路径。
- 目录标题清晰，但不做营销首页式巨型标题、欢迎横幅或仪表盘大数字。
- 主画布按内容决定组成；无关模块连标题、空卡片、入口都不显示。
- 不为了填满屏幕添加统计卡片。内容少时允许自然留白。
- 页面常态只保留一个主滚动区域；文件栏可独立滚动。避免嵌套多层滚动容器。

### 2.2 目录状态与显示规则

| 当前目录内容 | 默认呈现 | 必须不出现 |
|---|---|---|
| 只有子目录 | 简洁子目录列表，便于继续进入；可只在主区提供一次导航摘要 | loss、训练进度、空图片区、空推荐区 |
| 普通文本/数据文件 | 简短文件概况和可打开文件，不强行识别为训练 | 训练空卡片、无关分析按钮 |
| 只有图片 | 图片直接成为主内容 | 图片标签页、训练卡片 |
| 可解析 loss，无 nep.in | loss 曲线；目标代数和 ETA 不显示 | 为缺少 nep.in 隐藏可用 loss、虚构进度 |
| 可解析 loss，且有明确训练配置 | 曲线为主，目标/记录进度为辅 | 用文件更新宣称进程一定存活 |
| loss 存在但为空或不可解析 | 一行与该文件关联的说明，可点开文件；其他内容正常 | 巨大空坐标框或永久 loading |
| loss + 图片 | 紧凑训练区后直接接图片预览 | 必须换页才能看图 |
| 没有任何内容 | 一条空目录说明和返回上级入口 | 四五种模块的“暂无数据” |
| 权限/网络失败 | 当前目录级明确错误与重试，旧内容标为过期 | 把错误伪装成没有文件 |

识别规则必须基于实际数据能力。没有 loss 时，不发定时 loss 请求、不创建图表、不显示坐标控件。可保留后端 loss API 服务其他目录，用户反对的是无意义的入口和页面，不是要求删除有效后端能力。

### 2.3 一次操作就到达内容

- 点击左侧图片文件或画布缩略图：直接放大该图片；不先切页面，不更换主画布。
- 关闭图片：返回原目录、原滚动位置；支持 Esc、左右键浏览同目录图片，焦点回到来源。
- 点击文本/数据：打开一个统一的文件预览层；关闭后回到画布。不要再造常驻 Data 页。
- 文件默认只读；明确点击“编辑”后才出现保存/撤销等编辑控件。
- 数值文件默认给易读预览，绘图选项按需展开，不一次展示所有列开关和模式。
- 切换目录后，旧目录内容与请求立即失效；不把旧 loss 或旧图像留在新目录伪装为新结果。

## 3. Apple 风格参考与 GPUMDkit 自身表达

执行者读取可用的 `apple-ui-design` 技能。本次参考路径：`/Users/yanzihan/.codex/skills/apple-ui-design/SKILL.md`；其他环境按技能名称查找，找不到则按本文原则继续，不依赖该机器绝对路径。

借鉴清晰层级、克制配色、系统字体、适度留白和自然反馈。技能是参考，不机械套用 680px 全局宽度、48px 大标题、全毛玻璃卡片或所有按钮胶囊化。

GPUMDkit 的特色来自科学内容：稳定的曲线颜色、准确的坐标标签、清楚的输入/结果关系、原有品牌蓝；不是原子装饰背景、发光效果或拟物终端。

建议视觉基准：

- 系统无衬线字体；正文 14–15px、辅助信息 12–13px、目录标题 22–26px。
- 文件路径与数值局部使用等宽字体，不让整页变成命令行输出。
- 中性浅灰底、干净内容面；深色模式重设对比，不简单反色。
- 使用 4/8/12/16/24/32px 间距；目录标题与内容有呼吸感，相关控件保持靠近。
- 品牌蓝主要用于选中态和重要动作；大部分按钮为中性文字或轻量图标。
- 细分隔线优先，阴影仅用于真正浮层；禁止层层卡片套卡片。
- 交互反馈 120–180ms，减少动画时关闭；无持续闪烁光点、曲线呼吸动画或 hover 放大布局。
- 图标按钮有可访问名称和工具提示；触屏命中区域至少 44px，桌面控件也不能挤成难点中的小图标。
- 首屏不能出现多个同等醒目的蓝色主按钮。

## 4. 宽度、密度和响应式布局

不能只写“响应式”，必须按下列情形实际检查。

### 4.1 页面尺寸

- 顶栏约 56px；侧栏默认 232–256px，可折叠，不要求本轮增加拖拽调整。
- 主内容在剩余区域中居中，建议最大宽度 1120px；桌面内边距 24–32px，小屏 16px。
- 大屏不把曲线无限拉宽，也不把整页固定成窄长手机版。
- 以可用内容宽度决定列数，不仅根据屏幕设备名称。
- 浏览器放大到 125%、150%、200% 后应自然换行或切成窄屏布局，不能依靠缩小字号解决。
- 默认不展示固定底部状态栏或展开的终端区，避免压缩垂直空间。

### 4.2 图片排布

- 一张图片：自然成为主视觉，容器宽度约 640–840px，上限由图片比例和主区决定，不强制拉成满屏条形。
- 两张图片：空间足够时两列，每张至少约 320px；不足时单列。
- 多张图片：常规桌面 2–3 列，预览宽约 280–360px；不要挤出四五列看不清的科学图。
- 保持原始长宽比，完整显示图中坐标和图例；禁用 cover 裁切，禁止 CSS 拉伸。
- 初始缩略图可限定预览高度，但长图提供放大查看；图片底色不能被深色主题强行反色。
- 图片标题一行展示，长文件名省略但可查看全名；不把输入/输出/路径/时间等五行元信息压在每张图下。
- 超多图片渐进加载；默认画布能看到首批预览，其余可“显示更多”，不能用独立页面藏起全部图片。

## 5. Loss 图表专项重设计

这是本轮关键验收项，不能沿用 `width:100%; height:230px` 后只换颜色。

### 5.1 图表几何

- 常规桌面训练区域由“曲线 + 简短摘要”组成，曲线占主导。
- 当主区可用宽度足够时，曲线约 600–760px 宽、330–420px 高，旁边摘要约 180–220px。
- 推荐图表外框宽高比约 1.7–2.0；根据标签和图例分配内边距，不把外框比例当成绘图区比例。
- 不足以容纳上述两列时，摘要折成图上方的一行或图下方少量文字；图表宽度取容器宽，高度至少约 280px。
- 超宽屏仍限制图表宽度；在大屏上用对齐与留白建立秩序，不能靠横向拉伸填空。
- 窄屏可以提高相对高度，但不得产生整页横向滚动。
- 图例放在坐标区域外，允许换行；图例行数不挤占固定绘图区高度。
- 单点、短序列、长序列都能正确设置范围，不出现零范围、贴边裁切或一条线被压成像素。

### 5.2 坐标尺度：看得见，改得动，不混淆

默认保留现有 log-log 语义，以免悄悄改变用户对既有 loss 图的理解；它只是初始显示方式，不能硬编码为唯一方式。

- 图表旁提供简短的“坐标”入口，展开后可分别选择 X：Linear/Log，Y：Linear/Log。
- 常态用小号摘要明确当前尺度，例如 `X Log · Y Log`；不是展开设置才知道用了什么尺度。
- X 轴采用后端验证过的 generation 或 record index，标签与真实数据一致；不把降采样数组下标当代数。
- 不改变 scientific data，不自动平滑，不静默换单位，不为了让曲线好看自动切 scale。
- Log 模式对非正值有明确计数说明；不能把 0 改成任意 epsilon。无可显示正值时提供切换 Linear 的入口。
- 缺失值/无效值形成断点，不跨过缺失区间连出假趋势。
- 大跨度使用清楚的指数刻度，适当减少刻度数量；小跨度自动调整小数精度，不能所有标签都显示为 0.00。
- 自动范围包括可见系列，留适度边距；常数序列仍有非零轴范围。
- 不混合不同量纲做隐式归一化，不添加双 Y 轴；沿用已经核实的 loss 列含义。

### 5.3 缩放与用户控制

这里要区分三类 scale：页面响应式/浏览器缩放、图表坐标变换、用户查看的数值范围。三者不能相互覆盖。

- 图表支持明确触发的放大查看；放大层按视口重新计算几何，不能仅把低分辨率 canvas 拉伸。
- 图中区间缩放可作为展开控件，若实现需提供显式重置；禁止默认滚轮劫持整页滚动。
- 自动更新时保持用户选择的坐标模式、隐藏系列和查看范围；手动范围下不突然跳回全量。
- 回到完整范围有一个清楚入口；如果未实现区间缩放，则不要显示无效控件或声称支持。
- 图例可切换系列显隐，颜色与标签稳定；不能每次刷新重新分配颜色。
- 悬停/触摸显示实际采样点和对应 X 值，不把插值当真实数据。
- 保持总览，不默认只截取“最好看”的末段。追加多次训练时说明范围，避免误当单次训练曲线。

### 5.4 渲染和性能

- 监听实际容器尺寸变化；侧栏折叠、浮层打开、浏览器缩放后重新计算。
- canvas 按 devicePixelRatio 设置绘制分辨率；坐标、线条和鼠标位置都使用一致的逻辑像素。
- 已隐藏的容器不能按 0 宽度渲染；显示后再量取尺寸。
- 保留有界 loss API；大文件不通过普通文本预览接口读取。
- 降采样明确标注；不能凭抽样策略错过重要峰值而宣称完整保真。修改算法时用带尖峰合成数据验证。
- 图片、曲线和侧栏只在内容或布局发生变化时更新，避免轮询导致重绘闪烁。

## 6. 次要功能怎样保留而不制造复杂度

### 分析操作

- 仅当前目录有可执行动作才出现一个简洁“可用分析”区域。
- 用紧凑操作行或菜单呈现，不把每个命令变成多行大卡片。
- 每项显示用途，输入、命令和覆盖结果信息按需展开。
- 执行后结果直接出现在当前目录画布；若用户已经切目录，仅提示原目录已完成，不抢焦点。
- 仅用户明确点“查看结果”才打开浮层。

### 命令、日志、历史

- 通过顶栏“更多”中的命令入口按需打开同一个活动抽屉；平时不常驻三标签底栏。
- 有运行任务时用一个紧凑状态入口表明活动；点击查看输出，不把整块黑色终端自动铺开。
- 抽屉内可切输出/记录/命令，但只在用户打开时出现。
- 保留工作目录、退出码、耗时和结果绑定；错误有清晰原因。
- 面向用户的文字不堆 `bash -c`、API、锁、缓存等实现细节；必要的使用限制放帮助说明。

### 文件编辑

- 继续保留未保存保护、外部修改冲突和有界预览；视觉重写不能退回静默覆盖。
- 默认只读，编辑动作显式；保存/取消靠近编辑内容。
- 不展示对当前文件不适用的 Form、Data 等模式。
- 部分预览不能当完整文件保存。

## 7. 重构范围和不可回退项

允许完整重写 `web/index.html`、`web/style.css` 与前端布局/渲染层；可以拆分原生 JS 模块，但保持无构建、无 CDN、离线可用。不要为了减少改动沿用已经失败的布局。

- 数据来源目录固定，旧请求失效，跨目录返回不能覆盖当前画布。
- loss 大文件读取、文件冲突保护、预览上限和执行记录上下文。
- CLI 参数、输出文件约定、版本号、科学算法和已有曲线列含义。

重点复核当前 `lossFetchPath` 等共享变量防竞态方式：每次请求需捕获独立不可变路径与序号，不能依赖会被后续请求改写的同一个全局变量。

不运行训练、MD、DFT或调度任务，不新增远程访问方式，不自动安装大型依赖。

## 9. 验收矩阵：必须有浏览器证据

### 9.1 内容与动作

- 空目录：只有一次简洁空状态。
- 普通目录：无训练页面、无 loss 控件、无无意义 loss 网络请求。
- 图片目录：进入即看到图片；左侧单击图片直接放大，关闭不变页面。
- loss-only：有效数据可画，不需要伪造 nep.in。
- 空/损坏 loss：局部说明，其他图片和文件仍可用。
- loss + 多图：曲线比例合理，图片自然接续，没有顶层分页。
- 训练 A → 普通 B → 图片 C 快速切换：旧图表、请求和错误不串目录。
- 原目录执行完成但用户已离开：记录归属正确，不强制跳转。
- 外部修改后保存、未保存切文件：原有保护仍正常。

### 9.2 尺寸与视觉

至少检查 390×844、768×1024、1024×768、1440×900、1920×1080；在桌面检查 125%、150%、200% 浏览器缩放和至少一种高 DPI 场景。

- 宽屏 loss 不呈现长条；中屏不挤压成无法读的两列；窄屏坐标不截断。
- 横向科学图、方图、纵向长图完整不变形。
- 一张图、两张图、多图均有合理布局，不靠相同固定缩略图高度敷衍。
- 深浅色下曲线、文字、选中态和焦点可辨识，图片不被反色。
- 浏览器控制台无错误，网络请求没有无关 loss 轮询。

### 9.3 图表数据

使用合成夹具覆盖：单点、常数、小数小跨度、多个数量级、零/负值、缺失值、峰值、追加/截断、大于 512 KB 的 loss、多次训练记录。

检查四种 X/Y Linear/Log 组合；模式切换不改变原数据。检查缩放与刷新共存、刻度重叠、图例换行和悬停对应关系。不要只拿一条光滑曲线截图作为全部证明。

## 10. 什么情况算本轮失败

出现任何一项，继续修改，不交付为“完成”：

- 页面仍围绕固定 Overview/Data/Figures 功能分页。
- 无相关文件仍常驻 loss、训练或图片空卡片。
- 图片必须先进独立页面才能看到预览。
- loss 仍铺满宽屏且高度固定，坐标尺度硬编码且无法切换。
- 用更多卡片、标签、徽章、统计数字来解释原有复杂度。
- 只做截图壳子，真实数据、自动刷新或文件操作不能工作。
- 页面漂亮但丢失保存保护、跨目录隔离或原有可用操作。
- 没有实际浏览器检查，却声明视觉验收通过。
